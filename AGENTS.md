# Agent Instructions

<!-- HARNESS:BEGIN -->
## Harness

Start with the requested outcome and use the repository as the system of record.
Read `docs/WORKFLOW.md` and only relevant product, design, plan, code, and
validation material.

- Answers, explanations, reviews, diagnoses, plans, and status reports are
  read-only. Inspect only what is needed; change nothing.
- For a bounded change, inspect affected behavior and proof, implement, and
  validate. No control-plane operation is required.
- Use one `docs/plans/active/` file when work spans sessions, coordinates
  contributors, has dependencies, or needs recovery. Move it to
  `docs/plans/completed/` only after validation.
- Before editing, identify repository authority for each new externally
  observable policy. If materially different choices remain open, stop before
  edits; configurable defaults are not authority.
- For architecture, reliability, security, or quality invariant work, read
  `docs/patterns/encoding-invariants.md` and enforce only accepted rules.
- Report reusable agent friction. Change guidance, tools, runbooks, or validation
  for that purpose only when explicitly asked to use `$improve-harness`.
- Also pause when product intent remains ambiguous, recovery is difficult,
  validation is weakened, or authority is insufficient.
- Claim completion only with executable or observable evidence. Report outcome,
  changes, validation, and unresolved risks.

Harness has no task database or orchestration lifecycle. Use repository plans
and behavior-level proof; do not create parallel control-plane state.

## Exam Suite cho macOS

App luyện thi trắc nghiệm, dự án cá nhân của Nt0, Swift 6 + SwiftUI, macOS 15+, Apple silicon.
Một codebase, hai bản app: Học viên (`ExamSuite`) và Admin (`ExamSuiteAdmin`,
thêm Soạn đề). Đề là gói zip `.exam` = `exam.json` + `media/`.

### Nguồn thẩm quyền (đọc theo nhu cầu, theo thứ tự)

1. `docs/product/*.md`: hợp đồng sản phẩm hiện hành (overview, exam-format, scoring, exam-session).
2. `docs/decisions/`: ADR 0001–0013, bắt buộc tuân theo (0011, 0012: bản Android; 0013: bản iOS).
3. `docs/plans/active/`: exec-plan của giai đoạn đang làm; mỗi PR đúng một mục.
4. `schema/exam-v1.schema.json`, code và test: hành vi hiện tại.
5. `docs/product/plan-macos-v1.md`: kế hoạch đầy đủ (lộ trình, UX, rủi ro). Bản mobile: `docs/product/mobile.md`
   (chỗ Android khác macOS), `docs/product/plan-android-v1.md` (v1 xong, bản 0.1.0; exec-plan `docs/plans/completed/android-v1.md`; v1.1 lập plan khi Nt0 quyết),
   `docs/product/plan-ios-v1.md` (làm sau; hành vi theo macOS, không theo luật Android của `mobile.md`: Nt0 chốt 2026-10-30).
   DESIGN_BRIEF của Open Exam Suite chỉ **đọc qua link** (GPLv3): không chép code hay đề mẫu.

`Packages/ExamFeatures/.build/out/Products/Debug/ExamFeatures_*.bundle` mà đọc bản sao của nó trong từng
`<Test>.xctest/Contents/Resources/`. 2026-10-18: `verify_local.sh` incremental trên một worktree từng build ở commit cũ
(catalog chưa có `en`) làm mọi test tra `en` ra chữ tiếng Việt, cùng SHA chạy `--clean` thì đạt; bundle ở Products có
`en.lproj` nhưng Info.plist và `_CodeSignature` của lần build cũ. Đã thử: chữ ký cũ hay thiếu và cache CFBundle theo
thư mục không gây ra lỗi này; nghi bản sao trong `.xctest` không được chép lại (plan giai đoạn 5, Decisions 2026-10-18).
Gặp test tra `en` (hay ngôn ngữ mới) ra tiếng Việt sau khi catalog vừa có thêm ngôn ngữ: chạy `verify_local.sh --clean`,
hoặc xoá `Packages/ExamFeatures/.build` rồi chạy lại `check.sh`. Kiểm nhanh: `ls Packages/ExamFeatures/.build/out/Products/Debug/*.xctest/Contents/Resources/ExamFeatures_LibraryFeature.bundle/Contents/Resources`
phải có `en.lproj`. `verify_local.sh` (không `--clean`) tự xoá `Packages/ExamFeatures/.build` trước `check.sh` khi bundle
ở Products hay bản sao trong `.xctest` thiếu `<ngôn ngữ>.lproj` của catalog, hoặc bản sao khác bản ở Products (status ghi
"ExamFeatures build lại"); sau `check.sh` (mọi chế độ) kiểm lại đúng bản build vừa dùng, còn báo thì thất bại.

"plugin for module 'TestingMacros' not found" ở lần build incremental; đó là lỗi
toolchain, không phải lỗi test. Dùng `scripts/check.sh` (tự thêm
`-Xswiftc -plugin-path -Xswiftc <CLT>/usr/lib/swift/host/plugins/testing`) hoặc thêm cờ đó khi gọi tay.

### Quy tắc làm việc (chi tiết: `docs/process/review-and-merge.md`)

- Nhánh `feature/<giai-đoạn>-<mục>`; không push `main`; không tự merge.
- Merge chỉ khi commit status `local/verify` (từ `scripts/verify_local.sh`) xanh trên đúng SHA cuối; tóm tắt "đã test" không phải bằng chứng.
- Không kích hoạt GitHub Actions (không `gh workflow run`, không push tag) khi chưa được Nt0 yêu cầu (lý do ban đầu khi repo còn private: phút Actions có hạn, job macOS tính gấp 10; repo public chạy miễn phí, bật CI cho PR là quyết định sau của Nt0). Ngoại lệ (Nt0 chốt Q8 2026-10-22, ADR 0011): workflow `Android` (`.github/workflows/android.yml`) tự chạy theo PR chạm `android/` hoặc oracle chung; check `android` xanh trên SHA cuối là bằng chứng merge cho phần lint + test của `android/` (PR chạm `android/app/**` và cổng thêm `local/verify-android`); tag Android là `android-v*`. Hai job kiểm (`core-linux`, `apps-macos`) chỉ chạy tay khi Nt0 báo; gắn tag `v*` (do Nt0 yêu cầu) chỉ chạy job `release-dmg` (đóng hai DMG, tạo GitHub Release; Nt0 chốt 2026-10-19, docs/process/review-and-merge.md).
- Thay đổi chạm chấm điểm/chọn câu, đọc-ghi gói đề, lưu file soạn đề, ranh giới hai bản app, schema: rủi ro cao, cần review bằng phiên agent mới trước khi người duyệt.
- Không thêm thư viện khi chưa có ADR được duyệt (ADR 0006). Không sửa CI/branch protection khi chưa được yêu cầu.
- Quy tắc chấm điểm hay định dạng mơ hồ → dừng, hỏi; không tự chọn mặc định.
- Code và tên định danh bằng tiếng Anh; comment, tài liệu, chuỗi giao diện tiếng Việt (String Catalog có cả tiếng Anh).
- Nhịp làm việc mọi giai đoạn (Nt0 chốt 2026-10-18): review-and-merge.md mục 4: một `verify_local.sh --uitest` mỗi PR trên SHA cuối sau review, lúc làm chỉ chạy lớp UI test đã map, re-review chỉ rủi ro cao, xếp chồng tối đa một tầng, không PR chỉ tài liệu/kế hoạch, không thêm lớp kiểm trùng.

### Chuỗi giao diện (String Catalog, tiếng Việt là ngôn ngữ nguồn)

Chữ giao diện trong package mặc định tra bundle **chính** của app, không phải catalog của module, và quên chỉ bundle
không gây lỗi hay cảnh báo (docs/notes/g5-spike-pdf-l10n.md). Quy ước (docs/product/accessibility-localization.md):

- `Text("…", bundle: .module)` cho `Text` (giữ Markdown và nội suy của `LocalizedStringKey`).
- Mọi API khác nhận chuỗi (`Button`, `Label`, `Toggle`, `Picker`, `Section`, `TextField`, `Menu`, `LabeledContent`,
  `TableColumn`, `.help`, `.accessibilityLabel`, `.alert`, `prompt:`, `NSAlert`, `NSSavePanel`…) và chuỗi của model
  trình bày: `localized("…")`, hàm nội bộ của từng target trong `Localization/Localized.swift` (trả `String` đã tra
  catalog của target qua `InterfaceStrings.resolve`). Không gọi `String(localized:)` không có `bundle:`; không dùng kiểu
  `LocalizedStringKey` (tham số chữ của view nhận `String` đã tra). Nhánh `cond ? localized("A") : localized("B")`.
- Chữ không phải giao diện (log cho người phát triển, chuẩn hoá tìm kiếm) có chữ tiếng Việt thì thêm `// l10n-ignore`
  trên dòng. Lõi ExamKit/ExamFile và LibraryData, AuthoringData, ExamImport trả lỗi **có mã và đối số** (từ bước 7b);
  câu tiếng Việt của chúng (`message`, `errorDescription`, `logMessage`, `logDescription`) chỉ cho nhật ký, script, test.
  Giao diện dựng câu bằng catalog: `ErrorMessages.message(for:)` (LibraryFeature: `ValidationIssue`, `ExamFileError`,
  `LibraryError`, `FileProblemReason`…) hoặc `AuthoringMessages.message(for:)` (AuthoringFeature: `ExamEditError`,
  `ImportError`, `ImportIssueDetail`); lỗi ngoài Exam Suite qua `ErrorMessages.systemDescription(of:)`. Mã mới thì thêm
  câu vào hàm đó và vào test so tiếng Việt (`ErrorMessagesTests`, `AuthoringMessagesTests`).
- Số, phần trăm, ngày giờ theo locale của **ngôn ngữ giao diện**, không theo Region (`InterfaceLocale.current` của
  LibraryFeature: chỉ mã ngôn ngữ mà chữ của catalog ra, nên tới khi catalog có `en` luôn là `vi`; lịch Gregorian
  `InterfaceLocale.calendar`). Số nội suy trong `localized("…\(n)…")` tự theo nó; view SwiftUI theo `\.locale` của môi
  trường: scene mới của shell hay app gắn `.interfaceLocale()` (`\.locale` và lịch `\.calendar`; như
  `.defaultAppStorage`; luật `scene-locale`), gốc
  `ImageRenderer` cũng gắn; `Text(n, format: .number)` cho số đứng một mình, ngoài view `InterfaceLocale.number(_:)`/
  `percent(_:)` hoặc `.locale(InterfaceLocale.current)` (ngày thêm `calendar:`). Không `Locale.current`, không ghép `%`
  tay, không khoá chỉ có số trong catalog. Ngoại lệ: giá trị thang 1000 luôn số trơn qua `InterfaceLocale.scale1000(_:)`.
- Target mới có chữ giao diện: thêm `Resources/Localizable.xcstrings` (rỗng, `sourceLanguage` vi), `resources:` trong
  Package.swift, file `Localization/Localized.swift` như các target khác, và tên target vào `BUILT_APPS` của
  `check_localization.py`.
- Thêm/đổi chữ: viết thẳng tiếng Việt trong code, rồi đồng bộ catalog bằng `xcodebuild -exportLocalizations` (bảng
  Lệnh kiểm chứng) cho cả hai scheme và commit. Không sửa tay khoá; khoá `stale` thì xoá.
- Test: trong tiến trình không phải app (`swift test`), `InterfaceStrings` khoá ngôn ngữ nguồn `vi`, nên test so chữ
  tiếng Việt không đổi khi catalog có `en`. Tra theo ngôn ngữ cố định:
  `InterfaceStrings.resolve(key, bundle: <Module>.ModuleStrings.bundle, locale: Locale(identifier: "en"))`. Cả một luồng
  (model → PDF) ở tiếng Anh: `InterfaceStrings.$languageOverride.withValue(Locale(identifier: "en")) { … }` (task-local,
  `@testable import LibraryFeature`, chỉ cho test); snapshot tiếng Anh: `SnapshotHost.inLanguage(_:)` (ép cả tiến trình
  qua `processLanguageOverride`, chỉ trong suite chạy tuần tự). Code của app không dùng hai chỗ này (luật `test-hook`).
  Model không giữ chữ đã tra trong `static let` (tính mỗi lần đọc).
- Bản `en`: mọi khoá phải có (`check_localization.py --require-en` trong `check.sh`). Viết theo bảng thuật ngữ của
  accessibility-localization.md (thuật ngữ mới thêm vào bảng đề xuất, chờ Nt0 duyệt); Title Case cho menu, nút, tiêu đề,
  sentence case cho nhãn ô và câu; số nhiều bằng biến thể plural (`one`/`other`) hoặc substitution khi khoá có nhiều số;
  nhiều đối số thì số vị trí (`%1$@`). Sửa đúng `localizations.en` rồi `-exportLocalizations` hai scheme để Xcode ghi lại.
- Chữ app tự ghi vào **nội dung đề** (tên đề mới, tên phần mặc định, phần chung khi import) theo ngôn ngữ giao diện lúc
  tạo: target dữ liệu nhận tên từ tầng giao diện (`DefaultContentNames`, `sharedSectionTitle:`), không tự có catalog.
